
## Why Monitor?
- SSH/RDP = let admins **log in and manage** devices remotely
- Regular **monitoring** is also needed to spot **actual or possible faults** quickly
- Two main tools: **SNMP** and **Syslog**

---

## SNMP (Simple Network Management Protocol)

### What It Is
- Framework for **managing and monitoring network devices**

### Three Components
| Component | Role |
|-----------|------|
| **Network Management System (NMS)** | Central system that monitors all agents and displays info/alerts |
| **Managed devices** | Switches, routers, servers, etc. being monitored |
| **Agent** | Process running on the managed device that collects stats |

### MIB (Management Information Base)
- **Database** kept by each agent
- Holds **statistics about device activity**
  - Example: **frames per second** handled by a switch

### How It Works
- **Polling:** NMS asks each agent for MIB info at **regular intervals** and displays it
- **Traps:** Agent can **proactively notify** the NMS when a notable event happens
  - Example: a **port failure**
  - Trigger **thresholds** can be set per value
  - NMS shows traps as **alerts** for the admin

### Ports
| Port | Purpose |
|------|---------|
| **UDP/161** | Device queries (polling) |
| **UDP/162** | Traps |

### Versions
| Version | Status |
|---------|--------|
| SNMPv1, v2 | **Avoid** - security concerns |
| **SNMPv3** | **Preferred** - supports **authentication** between NMS and devices |

## Syslog

### Purpose
- Network management often needs **logs from many devices**
- Easier to review logs if **consolidated in one place**
- **Log collector** = gathers event messages from many devices into **one storage location**
  - Can also run **status/alerting dashboards**

### What Syslog Is
- Protocol + supporting software for **log collection**
- **De facto standard** for logging events from distributed systems
- Generated by: **routers, switches, UNIX/Linux servers, workstations**
- Syslog collector listens on **UDP/514**

### Syslog Configuration Options (example: OPNsense)
- Enable/disable forwarding
- Choose **transport protocol** (e.g., UDP)
- Choose which **applications** to log
- Set **logging levels**: info, notice, warn, error, critical, alert, emergency
- Choose **facilities**
- Enter the **hostname + port** of the log server (default **514**)

### Syslog Message Format
| Part | Description |
|------|--------------|
| **PRI code** | Calculated from **facility + severity level** |
| **Header** | **Timestamp** + **hostname** |
| **Message** | **Tag** (source process) + content (format depends on the app) |

---

## Quick Comparison

| Tool | Purpose | Port | Key Idea |
|------|---------|------|----------|
| **SNMP** | Monitor device stats and get alerts | UDP/161 (queries), UDP/162 (traps) | NMS polls agents + agents send traps |
| **Syslog** | Centralize logs from many devices | UDP/514 | Log collector aggregates event messages |

---

## Quick Summary
- **SNMP** = monitor devices using **agents**, **MIBs**, **polling**, and **traps**
- Use **SNMPv3** (authentication); avoid v1/v2
- **Syslog** = collects logs from many devices into one place (port 514)
- Syslog message = **PRI code + header (timestamp/host) + message (tag + content)**
